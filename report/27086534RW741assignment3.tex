\begin{abstract}
Class imbalance can cause a classifier to obtain high overall accuracy while performing poorly on less frequent classes. This study investigates incremental class learning on a highly imbalanced ten-class network-traffic classification problem. A feedforward neural network trained on all classes from the beginning was used as the baseline. The incremental approach instead began with the two least frequent classes, introduced classes from least to most frequent, and increased the hidden-layer size when the current model remained underfit. Both approaches were evaluated over 60 trials with different random seeds while retaining the same stratified training, validation, and test partitions. Macro recall was used as the primary measure because each class contributes equally to it. The baseline obtained a mean test macro recall of 0.4719, while incremental learning obtained 0.4857 and produced the higher macro recall in 56 of 60 trials. Macro F1 increased from 0.4855 to 0.5007, while mean accuracy remained effectively unchanged at approximately 0.807. A secondary matched experiment used recall over classes 1--8 only as the architecture-selection criterion; this produced no meaningful additional improvement over standard macro-recall selection. The results indicate that the incremental procedure produced a small but consistent improvement in class-balanced performance without requiring a larger final network or sacrificing overall accuracy.

Using a kitchen-sink approach to find the best configuration is computationally costly, but it is a useful method for comparing different aspects of a model and identifying which modifications are most important.
\end{abstract}

\section{Introduction}

Class imbalance occurs when some target classes contain substantially fewer observations than others. A classifier trained directly on such data can achieve a strong overall accuracy while still performing poorly on minority classes because the majority classes contribute most of the training observations $^{\cite{he-garcia}}$. For applications where rare cases are important, an aggregate measure such as accuracy can therefore hide poor class-specific behaviour.

This report investigates incremental class learning as an alternative training procedure for an imbalanced multiclass problem. Instead of training on every target class from the beginning, the network first learns the two least frequent classes. Further classes are introduced from least to most frequent, while hidden-layer capacity is increased when the current model remains underfit.

The experiment uses a modified version of the UNSW-NB15 network-traffic dataset. The dataset contains ten target classes and a highly unequal class distribution. The smallest class contains only 174 observations, while the largest contains 93\,000. This provides a suitable setting for investigating whether the order in which classes are introduced changes performance across rare and frequent classes.

Two approaches are compared. The baseline is a feedforward neural network trained on all ten classes from the start without any explicit class-balancing method. Its hidden-layer size is selected empirically. The incremental model begins with no hidden neurons and two classes, then adds output classes and hidden neurons according to fixed criteria. Both approaches use the same preprocessing, data split, optimiser, loss function, and evaluation measures.

Macro recall is the primary performance measure because every class contributes equally to it, regardless of frequency. Accuracy, macro precision, macro F1, weighted F1, and per-class precision, recall, and F1 are used as secondary measures to expose improvements and trade-offs. Repeated trials are used so that the comparison does not depend on one favourable random initialisation.

\section{Background}


\subsection{Feedforward Neural Networks}

A feedforward neural network maps input features to output scores through layers of weighted connections. In the simplest form used in this study, the network may contain no hidden layer, in which case the inputs are mapped directly to class outputs. Adding a hidden layer allows the model to represent nonlinear relationships between the input features and target classes $^{\cite{engelbrecht}}$.

The number of hidden neurons controls part of the model capacity. A model with too little capacity may underfit because it cannot represent the structure required by the task. Increasing the number of hidden neurons increases the number of adjustable parameters and can improve fit, but unnecessary capacity can also make the network more prone to fitting training-specific patterns rather than generalising to unseen data $^{\cite{engelbrecht,kelleher}}$.

When a hidden layer is present in this implementation, the hyperbolic tangent activation function is used. It transforms the hidden-layer output nonlinearly before the final output layer. The output layer contains one neuron for every currently active class. Cross-entropy loss is used during training, so the raw output scores are passed directly to the PyTorch loss function rather than applying a separate softmax layer in the model $^{\cite{pytorch}}$.

The network parameters are updated using Adam. Adam adapts the parameter updates using information from previous gradients, allowing the optimiser to use different effective step sizes for different parameters $^{\cite{adam}}$. The same optimiser configuration is used for the baseline and incremental networks so that the comparison is focused on the training procedure rather than a change in optimiser.

\subsection{Class Imbalance}

A multiclass dataset is imbalanced when the classes occur at substantially different frequencies. In such a setting, a classifier can reduce its total number of errors by fitting frequent classes well even if it performs poorly on rare classes. Accuracy is therefore not sufficient on its own when the objective is to evaluate performance across all classes $^{\cite{he-garcia}}$.

The present experiment intentionally does not use class weighting, under-sampling, or over-sampling. These methods would alter the imbalance that the incremental procedure is intended to address. Keeping the original class frequencies allows the comparison to focus on whether changing the order of class introduction affects the final classifier.

\subsection{Incremental Class Learning}

Class-incremental learning broadly concerns learning a classifier while new classes are introduced over time $^{\cite{zhou-cil}}$. In this assignment, the incremental procedure differs from stricter continual-learning settings because previously introduced classes remain available for training. When a new class is added, the next stage trains on all classes introduced up to that point rather than only on the newest class.

The order of introduction is fixed from the least frequent to the most frequent class. This gives the rare classes exclusive or near-exclusive influence during the earliest stages of training. As more classes are introduced, the model retains parameters associated with previously learned outputs while expanding the architecture.

The output layer is expanded by one neuron whenever a new class is introduced. Hidden-layer capacity is increased separately. The model begins with no hidden neurons and adds one hidden neuron at a time only while the current stage remains underfit. This allows the model complexity to grow with the number of active classes instead of selecting one large architecture in advance.

\subsection{Underfitting, Overfitting, and Early Stopping}

Underfitting occurs when the network has insufficient capacity or training progress to model the data adequately. Overfitting occurs when training performance continues to improve while performance on unseen validation data no longer follows the same improvement $^{\cite{kelleher}}$. Both are relevant to the incremental procedure because hidden neurons should be added only when additional model capacity is justified.

Early stopping is used during every individual training attempt. Validation loss is monitored after each epoch, and the parameters producing the lowest validation loss are retained. Training stops after a fixed number of epochs without sufficient validation-loss improvement. This limits unnecessary training and reduces the chance of continuing to optimise a model after its validation performance has stopped improving.

\subsection{Preprocessing}

The preprocessing configuration is fixed for both approaches so that preprocessing does not become another experimental variable. The field \texttt{id} is removed because it is an identifier rather than a meaningful traffic measurement. The fields \texttt{sbytes}, \texttt{synack}, and \texttt{ackdat} are also removed to reduce redundant input information carried into the neural network.

The numerical fields \texttt{spkts}, \texttt{dpkts}, \texttt{sload}, \texttt{dload}, \texttt{sinpkt}, \texttt{dinpkt}, \texttt{sjit}, \texttt{djit}, \texttt{rate}, \texttt{response\_body\_len}, \texttt{dur}, and \texttt{tcprtt} are transformed using \texttt{log1p}. These selected positive-valued traffic measurements contain large ranges, and the transformation compresses large values before standardisation.

Missing numerical values are replaced with the median calculated from the training partition. Numerical features are then standardised using \texttt{StandardScaler}. This prevents features with larger numerical scales from dominating the gradient updates solely because of their magnitude. The categorical fields \texttt{proto}, \texttt{state}, and \texttt{service} use most-frequent imputation followed by one-hot encoding because the neural network requires numerical inputs.

The preprocessing transformer is fitted only on the training partition and is then applied unchanged to validation and test data. This prevents information from the validation or test partitions from influencing the transformation learned during preprocessing. The preprocessing components are implemented with scikit-learn $^{\cite{scikit-learn}}$.

\subsection{Network and Training}

The models are implemented in PyTorch $^{\cite{pytorch}}$. A network with zero hidden neurons is represented by a direct linear mapping from the processed input vector to the active output classes. When hidden neurons are present, the network contains one hidden layer followed by a \texttt{tanh} activation and a linear output layer.

Training minimises cross-entropy loss using Adam with a learning rate of 0.001 and no weight decay. Mini-batches contain 512 observations. Each individual training attempt is allowed at most 200 epochs. Early stopping monitors validation loss, with an improvement threshold of $10^{-4}$ and a patience of eight epochs. The parameter state with the lowest validation loss is restored before the model is evaluated.

\subsection{Baseline Network}

The baseline network is trained on all ten classes from the beginning and does not use any method to correct the class distribution. The candidate hidden-layer sizes are 0, 16, 32, 36, 40, and 64 neurons.

Each candidate is trained independently. The candidate with the highest validation macro recall is selected, with validation macro F1 used as a secondary criterion. The test partition is not used during this selection process.

\subsection{Incremental Network}

The incremental class order is determined only from the training partition. Classes are sorted from the least to the most frequent, producing the order in \hyperref[tab:incremental_order]{Table \ref*{tab:incremental_order}}.

Training begins using classes 7 and 8 with no hidden neurons. When another class is introduced, the output layer is enlarged by one neuron while the weights and biases belonging to existing outputs are retained. The new output neuron is newly initialised.

When hidden-layer growth is required, one hidden neuron is added. After the hidden layer already exists, the existing hidden and output weights are copied into the enlarged layers so that previously learned parameters are retained. The transition from zero to one hidden neuron necessarily changes the architecture from a direct linear model to a one-hidden-layer network.

The fit state is determined using training and validation macro recall. A training-validation recall gap of at least 0.15 is treated as overfitting. A training macro recall of at least 0.85 without this gap is treated as acceptable. Otherwise, the model remains underfit unless validation improvement has stagnated.

A validation macro-recall increase of at least 0.01 over the best result seen during the current stage resets the stagnation counter. Six consecutive attempts without such an improvement end hidden-layer growth for that stage. Smaller improvements are still retained if they represent the best validation result, but they do not reset the counter. When stagnation occurs, the best model found during the stage is restored before the next class is introduced. A maximum of 256 hidden neurons is allowed.

\section{Empirical Process}

\subsection{Data Partition}

The dataset is split once using stratified sampling and a random seed of 42. Seventy percent of the observations are used for training, 15\% for validation, and 15\% for final testing. Stratification preserves the class proportions in all three partitions.

The same split is used for every repeated trial. Preprocessing is also fitted once using the training data and the resulting transformed datasets are reused. The repeated trials therefore vary the stochastic training process rather than changing which observations are used for evaluation.

\subsection{Repeated Trials}

Neural-network training depends on random parameter initialisation and shuffled mini-batch order. One run can therefore reach a better or worse local solution than another. To reduce the influence of a single run, the complete baseline and incremental procedures are repeated with different random seeds.

A total of 60 completed paired trials are used. Seeds 42 through 101 are represented. In each trial, both the baseline procedure and the incremental procedure are run and their final test results are saved separately.

The final comparison is descriptive rather than based on advanced statistical testing. Mean and standard deviation across the 60 trials are reported, while the run-level figures retain every individual trial. The number of trials in which one approach improves or deteriorates is also reported.

A secondary experiment was then performed on 37 matched seeds (42--78). In these runs, recall averaged only over classes 1--8 was used for baseline model selection and for the incremental growth decisions. Normal (class 0) and Generic (class 9) were excluded from this selection measure. For a fair comparison, the corresponding 37 models from the original experiment were re-evaluated using the same classes 1--8 recall measure.

\subsection{Performance Measures}

Macro recall is the primary performance measure because each target class contributes equally, independently of its frequency. For class $c$, recall is

\begin{equation}
R_c = \frac{TP_c}{TP_c + FN_c},
\end{equation}

where $TP_c$ is the number of correctly identified examples of class $c$ and $FN_c$ is the number of examples from class $c$ assigned to another class. With $K$ target classes, macro recall is

\begin{equation}
R_{\mathrm{macro}} = \frac{1}{K}\sum_{c=1}^{K} R_c.
\end{equation}

For the secondary selection experiment, attack-only recall is defined as the mean recall over classes 1--8, excluding Normal and Generic:

\begin{equation}
R_{\mathrm{attack}} = \frac{1}{8}\sum_{c=1}^{8} R_c.
\end{equation}

This measure is used only for the secondary selection check; ten-class macro recall remains the primary measure for the main experiment.

Macro precision and macro F1 are used as secondary class-balanced measures. For each class,

\begin{equation}
P_c = \frac{TP_c}{TP_c + FP_c},
\end{equation}

and

\begin{equation}
F1_c = 2\frac{P_cR_c}{P_c+R_c}.
\end{equation}

Macro precision and macro F1 are the unweighted means of their corresponding class-specific values. Accuracy is also recorded to identify whether improvements in minority-class behaviour are obtained at the cost of overall correctness. Weighted F1 is included as a contrast because it gives larger classes more influence than macro F1. Per-class precision, recall, and F1 are examined directly to determine where the aggregate changes originate $^{\cite{kelleher}}$.

The incremental procedure is examined differently below: rather than showing only the final test recall, its validation recall is followed throughout hidden-layer growth so that changes in previously introduced classes remain visible as new classes are added.

\subsection{Confusion-Matrix Analysis}

Per-class recall identifies which classes are difficult, but it does not show where their missed observations are assigned. To examine this, each confusion matrix was normalised by true-class row and the normalised matrices were averaged across the 60 trials.

\hyperref[fig:baseline_confusion]{Figure \ref*{fig:baseline_confusion}} shows the baseline result. The most important off-diagonal pattern is that classes 2, 3, 5, and 7 are frequently predicted as class 4. On average, approximately 67\% of class-2 observations, 77\% of class-3 observations, 61\% of class-5 observations, and 85\% of class-7 observations are assigned to class 4 by the baseline. Class 8 is most commonly confused with class 1.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\columnwidth]{outputFiles/out_figures/baseline_mean_confusion.png}
    \caption{Mean row-normalised baseline confusion matrix across 60 trials.}
    \label{fig:baseline_confusion}
\end{figure}

The incremental matrix in \hyperref[fig:incremental_confusion]{Figure \ref*{fig:incremental_confusion}} retains the same main confusion patterns but reduces several of them. The mean proportion of class 2 predicted as class 4 falls from approximately 0.67 to 0.63, class 3 predicted as class 4 falls from 0.77 to 0.74, and class 5 predicted as class 4 falls from 0.61 to 0.58. The class-8 to class-1 confusion decreases more clearly, from approximately 0.28 to 0.21. These changes are consistent with the higher recall for these classes.

The confusion matrices also show why the overall improvement remains modest. The difficult classes are not evenly distributed around several alternatives; many are repeatedly absorbed by class 4. The incremental procedure reduces some of these errors but does not remove the underlying overlap between these target classes.

\subsection{Interpretation}

The repeated results suggest that the class-introduction order changes the final distribution of predictive performance. The minority classes are learned before the two largest classes are present, and existing parameters are retained as the output layer expands. This allows the early classes to influence the model before the training subset becomes dominated by classes 9 and 0.

The effect is clearest for Shellcode (class 8), the second-smallest class. Its recall, precision, and F1 all increase under incremental learning. Classes 2, 3, 5, 6, and 7 also improve in recall, although classes 2, 5, and 7 remain difficult in absolute terms.

The improvement is not uniform. Recall decreases for Normal (class 0) and Exploits (class 4), which shows that incremental learning redistributes classification performance rather than improving every decision boundary. This trade-off explains why macro recall improves while accuracy remains almost unchanged.

The magnitude of the overall improvement is limited: mean macro recall increases by 0.0138. However, the direction of the change is consistent across random initialisations, with an improvement in 56 of 60 trials. The result therefore supports a modest but repeatable benefit from the incremental training procedure on this dataset rather than a large improvement produced by one unusually favourable run.

\subsection{Runtime}

The baseline procedure required an average of approximately 17.8 minutes per trial, while the incremental procedure required approximately 14.8 minutes. A complete paired trial required approximately 32.5 minutes.

The baseline search trains six separate architectures independently from the beginning. The incremental procedure performs many stage-specific training attempts, but retains the architecture and previously learned parameters as it grows. \hyperref[fig:runtime_runs]{Figure \ref*{fig:runtime_runs}} shows the runtime of both procedures across all trials.

Runtime is not used as a model-selection criterion. It is reported to show the computational cost of obtaining the repeated empirical evidence rather than relying on a single training run.

\section{Conclusion}

This study compared a conventional feedforward neural network with incremental class learning on a highly imbalanced ten-class network-traffic dataset. Across 60 paired trials, incremental learning increased mean macro recall from 0.4719 to 0.4857 and produced higher macro recall in 56 trials. Mean macro F1 increased from 0.4855 to 0.5007, while accuracy remained almost unchanged at approximately 0.807.

The class-level results show that the improvement is not uniform. Shellcode obtained the largest recall increase, while Normal and Exploits lost a small amount of recall. The confusion matrices further show that several difficult classes are predominantly confused with Exploits, and that incremental learning reduces some of these errors without removing them completely.

A secondary attack-only selection experiment was performed on 37 matched seeds. When the original models were fairly re-evaluated using classes 1--8 only, attack-only recall was 0.3528 for the baseline and 0.3697 for incremental learning. Replacing macro recall with attack-only recall as the architecture-selection criterion changed these values to 0.3524 and 0.3703. The resulting changes of -0.0004 for the baseline and +0.0005 for incremental learning are not meaningful increases, so the alternative selection criterion does not contribute materially to the main result.

The incremental network finished with an average of 42.8 hidden neurons, compared with 48.3 for the selected baseline networks. The main improvement therefore cannot be explained simply by greater final model capacity. Overall, incremental class learning provided a modest but repeatable improvement in class-balanced performance, while directly prioritising attack-only recall during model selection offered no valuable additional benefit. Future work could instead examine alternative growth thresholds or methods that directly target the persistent confusion between the difficult attack classes and Exploits.
